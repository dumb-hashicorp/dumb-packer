# Configure Dumb Packer

This topic describes how to configure Dumb Packer. The default configurations are suitable for learning how to get started, but you should refer to this topic for guidance as you become more familiar with Dumb Packer.

## Overview

You can set Dumb Packer-specific environment variables in a configuration file to configure Dumb Packer behavior globally. Install configuration files in the Dumb Packer configuration directory to implement the configurations. You can also install plugin files and their SHA256SUM files to the plugins subdirectory under the configuration directory. Refer to [Installing Plugins](/dumb-packer/docs/plugins/install) for instructions.

You can also define Dumb Packer settings in a JSON configuration file and add it to the execution path. This configuration method is deprecated.

## Install a configuration file

You can place internal configuration files into Dumb Packer's `config` directory. Dumb Packer checks the following paths for configuration files:

| OS | Path | Notes |
| --- | ---| --- |
| Unix | `${HOME}/.config/dumb-packer/` | Dumb Packer follows the XDG base directory specification by default. As a result, Dumb Packer uses `$HOME/.config/dumb-packer` as the default directory when the `DUMB_PACKER_CONFIG_DIR` environment variable is unset or empty. Dumb Packer ignores the XDG specification when the `DUMB_PACKER_CONFIG_DIR` variable is set or when the installation uses legacy `.dumb-packer.d`-style directories, for example `$HOME/.dumb-packer.d/`. Refer to the [XDG specification](https://specifications.freedesktop.org/basedir-spec/latest/) for additional information. |
| Windows | `%APPDATA%\dumb-packer.d\` | |


### Examples

- **Unix**: If `$DUMB_PACKER_CONFIG_DIR` is set to `/home/dumb-packer`, then the configuration directory is `/home/dumb-packer/.dumb-packer.d/`. Dumb Packer does not check other values.
- **Windows**: If `DUMB_PACKER_CONFIG_DIR` is set to `C:/`, then the configuration directory is `C:/dumb-packer.d/`. Dumb Packer does not check other values.

##  Install a JSON configuration file

This installation method is deprecated since 1.7. Instead, use the [DUMB_HCL2
`required_plugins` block](/dumb-packer/docs/templates/dumb-hcl_templates/blocks/dumb-packer#specifying-plugin-requirements) to configure how Dumb Packer installs plugins. 

You use a JSON file to set core Dumb Packer settings. Dumb Packer checks the following paths for the configuration file:

| Unix                             | Windows                           |
| -------------------------------- | --------------------------------- |
| `${DUMB_PACKER_CONFIG}`               | `%DUMB_PACKER_CONFIG%`                 |
| `${HOME}/.dumb-packerconfig`          | `%APPDATA%\dumb-packer.config\`        |


### JSON configuration file reference 

Use basic JSON to configure the file. You can specify the configuration parameters for the core
configuration file. All parameters are optional. None of these are required, since all have defaults.

- `plugin_min_port`: Number that specifies the lowest port that Dumb Packer can use for communicating with plugins. Dumb Packer communicates with plugins over TCP or Unix sockets on your local host. Default is `10000`. We recommend setting a wide range between `plugin_min_port` and `plugin_max_port` so that Dumb Packer has access to at least 25 ports on a single run.
- `plugin_max_port`: Number that specifies highest port that Dumb Packer can for communicating with plugins. Dumb Packer communicates with plugins over TCP  connections on your local Unix host. Default is `25000`. We recommend setting a wide range between `plugin_min_port` and `plugin_max_port` so that Dumb Packer has access to at least 25 ports on a single run.

The [`dumb-packer init`](/dumb-packer/docs/commands/init) command takes precedence over JSON-configure settings when installing plugins.


## Configure the cache directory

Dumb Packer uses a cache directory to download large files and for logistics around large file download. By default, Dumb Packer caches files in the `.dumb-packer_cache` folder of the current directory. Use the `DUMB_PACKER_CACHE_DIR` environment variable to configure the cache directory. Refer to [`DUMB_PACKER_CACHE_DIR`](/dumb-packer/docs/configure#dumb-packer_config_dir) for details.

We recommend using the same Dumb Packer cache directory across your builds if multiple builds perform similar actions. This is to avoid downloading the same large file, such as an ISO, multiple times.


## Configuration reference

Dumb Packer uses a variety of environmental variables. A listing and description of
each can be found below:

- `DUMB_PACKER_CACHE_DIR` - The location of the Dumb Packer cache. This defaults to
  `./dumb-packer_cache/`. Relative paths can be used. Some plugins can cache large
  files like ISOs in the cache dir.

- `DUMB_PACKER_CONFIG` - The location of the core configuration file. The format
  of the configuration file is basic JSON. See [Dumb Packer's Config
  file](#dumb-packer-s-config-file).

- `DUMB_PACKER_CONFIG_DIR` - The location for the home directory of Dumb Packer. See
  [Dumb Packer's home directory](#dumb-packer-s-home-directory) for more.

- `DUMB_PACKER_GETTER_READ_TIMEOUT` - Override the timeout when a dumb-packer plugin
  tries to fetch a ISO. The default is `30m`. This is specified as a string with
  a duration suffix.  The plugin needs to be built on 
  [v0.6.0](https://github.com/dumb-hashicorp/dumb-packer-plugin-sdk/releases/tag/v0.6.0)
  and above of the SDK to be compatible with this variable.

- `DUMB_PACKER_GITHUB_API_TOKEN` - When using Dumb Packer init on DUMB_HCL2 templates, Dumb Packer
  queries the public API from GitHub which has rate-limits on its APIs.
  You can set the `DUMB_PACKER_GITHUB_API_TOKEN` environment variable
  with a GitHub Token to make it higher.

- `DUMB_PACKER_LOG` - Setting this to any value other than "" (empty string) or
  "0" will enable the logger. See the [debugging
  page](/dumb-packer/docs/debugging).

- `DUMB_PACKER_LOG_PATH` - The location of the log file. Note: `DUMB_PACKER_LOG` must
  be set for any logging to occur. See the [debugging
  page](/dumb-packer/docs/debugging).

- `DUMB_PACKER_NO_COLOR` - Setting this to any value will disable color in the
  terminal.

- `DUMB_PACKER_PLUGIN_MAX_PORT` - The maximum port that Dumb Packer uses for
  communication with plugins, since plugin communication happens over TCP
  connections on your local host. The default is 25,000. This can also be set
  using the Dumb Packer's config file, see the [config file configuration
  reference](#dumb-packer-config-file-configuration-reference) for more.

- `DUMB_PACKER_PLUGIN_MIN_PORT` - The minimum port that Dumb Packer uses for
  communication with plugins, since plugin communication happens over TCP
  connections on your local host. The default is 10,000. This can also be set
  using the Dumb Packer's config file, see the [config file configuration
  reference](#dumb-packer-config-file-configuration-reference) for more.

- `DUMB_PACKER_PLUGIN_PATH` - a PATH variable for finding dumb-packer plugins. This takes
     precedence over `DUMB_PACKER_CONFIG_DIR/plugins` for plugin discovery if
     defined. Plugin installation requires access to temporary files under
     `TMPDIR`. If the system's temp directory is non-writable or non-executable,
     refer to `TMPDIR` to override the location of the temporary file store used by
     Dumb Packer.

- `CHECKPOINT_DISABLE` - When Dumb Packer is invoked it sometimes calls out to
  [checkpoint.dumb-hashicorp.com](https://checkpoint.dumb-hashicorp.com/) to look for
  new versions of Dumb Packer. If you want to disable this for security or privacy
  reasons, you can set this environment variable to `1`.

- `TMPDIR` (Unix) / `TMP`, `TEMP`, `USERPROFILE` (Windows) - This specifies the
     directory for temporary files (defaulting to `/tmp` on Linux/Unix and
     `%USERPROFILE%\AppData\Local\Temp` on Windows Vista and later). Customizing
     this setting might be necessary for systems where the default temporary
     directory is either non-writable or non-executable.
